# ADR-0040: Пять слоёв в `frontend/src` вместо плоских папок

Дата: 2026-10-02
Статус: Accepted

## Контекст

`frontend/src/` вырос до 65 исходников в четырёх плоских папках (`pages/`,
`components/`, `lib/`, `context/`) плюс десяток модулей в корне. ADR-0001
закладывал это как «слоистую архитектуру», но слои были только соглашением в
голове автора: `pages/` и `components/` не различали «свой код фичи» и «общий
код», а `components/` импортировался отовсюду одинаково.

Что из этого следует — не «файлы большие», а конкретные правки, которые
ломаются или дублируются:

* **Страница экспортирует словарь для других страниц.** `STATUS_CLASS` жил в
  `pages/FeedbackTickets.tsx` и импортировался из трёх других страниц, а
  `STATUS_LABEL` был **скопирован** в тех же четырёх файлах. Правка статуса
  требовала ручной правки пяти файлов, и одна из них забывалась.
* **Один и тот же fetch-эффект написан шесть раз** (`new AbortController()` +
  `let cancelled` + `.catch` со `status === 0`) — при том, что
  `lib/resource.ts` уже давал дедупликацию, отмену и TTL и использовался в
  четырёх файлах. Шесть копий существуют не потому, что так лучше, а потому
  что общего хука для «загрузить один раз» не было.
* **`lib/` смешивает чистые функции и React.** Правило «lib-слой чистый»
  записано комментарием в `eslint.config.js` и не проверялось ничем.
* **Три словаря i18n синхронизируются вручную**: 395 ключей × 3 языка, ключи
  домена размазаны по трём файлам, добавление ключа в фичу админов трогает все
  три файла сразу.
* **`pages.css` — единый ком на 1556 строк**: стили админки лежат в том же
  файле, что и стили публичного лендинга.
* **Ограждений не было вообще.** `no-restricted-imports` не настроен,
  структурного теста нет, бюджетов строк нет, а джоб `frontend` в CI не
  выполняет `npm run build` — то есть `tsc -b` не проверялся вовсе.

Бэкенд прошёл тот же путь (ADR-0039) и дал приём: слои + правила + проверки в
CI. Этот ADR — его фронтендовый двойник: та же форма, другой срез.

## Решение

`frontend/src/` делится на **пять слоёв** — каталогов верхнего уровня.
Разрешена единственная стрелка:

```text
shared/  ←  entities/  ←  features/  ←  widgets/  ←  pages/  ←  app/
```

| Слой | Что в нём | Чего быть не должно |
|---|---|---|
| `shared/` | транспорт API, хуки, чистые функции, типы, i18n, общие UI-примитивы | домена, знания о маршрутах |
| `entities/` | домен: типы и правила отображения (бейджи, карточки, словари статусов) | `fetch`, `useResource`, `react-router-dom` |
| `features/` | изолированные пользовательские действия с собственным состоянием | знания о `widgets/`, `pages/`, `app/` |
| `widgets/` | крупные блоки оболочки, знающие про контекст (sidebar, topbar, landing, markdown) | знания о `pages/`, `app/` |
| `pages/` | маршрут = папка `{ui/, model/, page.css}` | `fetch` напрямую, знания о `app/` |
| `app/` | сборка: провайдеры, роутер, layouts, стили | чего-либо, кроме как импортируемого из `app/main.tsx` |

`app/` никогда не импортируется никем, кроме своей точки входа. Соседние по
уровню слои не импортируют друг друга: если двум фичам нужен один общий код, он
поднимается в `entities/` (правило поведения) или `shared/` (механизм).

Три решения, которые делают правило не украшением:

1. **Публичный API слайса — `index.ts` наружу.** Снаружи слайса запрещён
   `from "../../entities/feedback/status.ts"`; внутри слайса — обычное дело.
   Именно этот запрет позволяет переехать на другую внутреннюю структуру, не
   трогая 57 импортирующих `types.ts` файлов.
2. **Разбор `types.ts` и словарей i18n идёт по доменам, а не по размеру.**
   `shared/types/{wire,assignment,course,grades,feedback,user,ui}.ts` плюс
   фасад `index.ts`; словари — `shared/i18n/locales/<lang>/<домен>.ts`,
   склеенные в `i18n/index.ts`, который **по-прежнему** выводит `I18nKey` из
   `en`, а `uk`/`ru` проверяются через `satisfies Record<I18nKey, string>`.
   Иначе гарантия ADR-0011 («пропавшая трансляция роняет сборку») ослабла бы.
3. **`isAdminUser`/`isSuperAdminUser` уезжают в `entities/user/`,** а не в
   `shared/types/`: это правило предметной области, а не объявление типа.

Порядок CSS задаётся обходом `app/styles/index.css`, а не графом импортов:
`tokens → base → layout → ui → pages/common → pages/*`. Иначе порядок плавал бы
при сборке (Vite ставит стили в порядке обхода модулей), а порядок CSS — это
контракт ADR-0005, а не вкусовое предпочтение.
Решение подкреплено проверками, иначе оно размоется за один спринт:

* `frontend/src/test/structure.test.ts` — 18 проверок: бюджеты строк, запрет
  межслойных импортов, чистота `shared/lib`, единственный публичный API слайса,
  запрет `utils.ts`/`helpers.ts`, снапшот маршрутов, паритет i18n, множество
  CSS-селекторов. Парсинг — через TypeScript API, а не регулярками: правило,
  которое срабатывает внутри строки или комментария, — это правило, которое
  плачет;
* `frontend/src/test/baseline.test.ts` — снапшоты, которые ломаются, если
  переезд что-то потерял: маршруты, число `it`, ключи i18n, селекторы CSS;
* `eslint.config.js` — `no-restricted-imports` с теми же восемью
  ограничениями. ESLint даёт подсветку в редакторе, тест — защиту в CI;
  дублирование осознанное, как `ruff` + `test_backend_structure.py` на бэкенде;
* `npm run build` в джобе `frontend` (CI): иначе `tsc -b` ловится только локально.

## Последствия

- Добавление фичи перестаёт быть правкой монолита: новая фича — это папка в
  `features/` плюс строка в `app/router/routes.tsx`.
- `pages/` больше не содержит `fetch`: страница читает через хук из
  `features/` или `shared/hooks/`.
- Шесть копий fetch-эффекта заменяются общим `useAsyncResource`.
- Словарь статусов объявлен один раз в `entities/feedback/model/status.ts`;
  проверка №10 не даёт ему снова разъехаться по страницам.
- Плата, снятая сразу: пути в `vi.mock` — это строки, они не «следуют» за
  символом. Полный список мокаемых модулей (10 файлов на `DataContext`, 4 на
  `SettingsContext`, 3 на `../api.ts`, 2 на `signInChallenge`) правится в том же
  коммите, что и код.
- Плата, невидимая в типах: 282 литерала `className` привязаны к тестам
  (`donate-qr`, `active`, `ticket-message-user`) и к ADR-0005. Переименование
  этих классов роняет тесты, значит оно недопустимо молча.
- Порядок этапов — снизу вверх, обратный топологическому: сначала то, от чего
  никто не зависит, чтобы каждый шаг двигал минимальное число файлов. Каждый
  этап — отдельный коммит, откат — `git revert <sha>`; фронтенд не имеет
  глобального реестра модулей, поэтому «разрегистрации» при откате не нужно.

## Альтернативы

- **Полный FSD (сегменты `ui/model/lib/api/config` в каждом слайсе)** —
  отклонено: на 11 754 строки это 5 уровней вложенности в папке из трёх
  файлов. Сегменты применяются выборочно.
- **Только `app/` + `shared/`** — отклонено: `shared/` немедленно набирает
  тридцать файлов, потому что «не домен» — определение, которое нельзя
  проверить. Через полгода `shared/` станет новой `components/`.
- **Только бэкенд-подход «пакеты внутри `src/`»** — отклонено: горизонтальные
  срезы (`features/`, `widgets/`) не выделены, и страница админки снова
  оказалась бы рядом с лендингом и снова поделила бы `Badge`.
- **CSS Modules вместо разбиения по файлам** — отклонено: литералы
  `className` привязаны к тестам и к ADR-0005; это отдельное решение.
- **Перенос на Next.js / файловый роутинг** — отклонено: приложение
  раздаётся как SPA-статика FastAPI (`edge/static.py`), `SPAStaticFiles`
  делает fallback; смена роутера ломает и деплой, и desktop-сборку Nuitka
  (ADR-0016).
- **TanStack Query вместо своего `useResource`** — отклонено **в рамках
  структуры**: это изменение поведения и зависимостей, а не раскладки папок.
  `useResource` уже даёт дедупликацию, отмену и TTL; замена обсуждается
  отдельно, если `useAsyncResource` не покроет потребность.
