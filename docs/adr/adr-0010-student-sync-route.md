# ADR-0010: Чтение заданий через студенческий маршрут (submissions + point-get)

Дата: 2026-09-14
Статус: Accepted

## Контекст

При первой реальной синхронизации `GET /courses/{courseId}/courseWork` вернул
`403 The caller does not have permission`, хотя в Google-аккаунт пользователь
вошёл успешно. Диагноз: **`courses.courseWork.list` доступен только
учителям** — студент не может перечислить все задания курса этим эндпоинтом,
независимо от того, какие scope у токена (формулировка про «слившиеся» scope
точная: оба read-scope уже выданы, но это не даёт прав на bulk-list).

## Решение

Студенческий маршрут (две точки API, обе разрешены студентам):

1. `studentSubmissions.list(courseId, courseWorkId="-", userId="me")` —
   перечисляет **все** собственные сабмишены курса одним вызовом (курсворк
   обнаруживается через сабмишены, а не наоборот);
2. точечный `courseWork.get(courseId, courseWorkId)` по каждому уникальному
   `courseWorkId` — детали задания: заголовок, описание, dueDate/dueTime,
   maxPoints, материалы, alternateLink.

Сопутствующие технические решения:

- **Таймауты на транспорте.** google-api-python-client 2.200.0 убрал аргумент
  `timeout` из `HttpRequest.execute()`, поэтому таймаут задаётся на уровне
  `httplib2.Http(timeout=30)` через `AuthorizedHttp` в
  `classroom_api.build_service()`. Зависший сокет не должен вечно блокировать
  синк.
- **Параллельность без гонок.** Точечных GET может быть сотни
  (≈1 на задание). `ThreadPoolExecutor(max_workers=8)` сокращает синк с минут
  до ~2; при этом `httplib2/discovery` не потокобезопасны, поэтому каждый
  воркер строит **свой** клиент через `threading.local()` (общий клиент из 8
  потоков давал segfault в ssl-слое).
- **Батчинг отклонён.** `BatchHttpRequest` (до 1000 вызовов одним запросом)
  против Classroom вернул 404 — Google не поддерживает его для этого API.
- **Архивные и покинутые курсы игнорируются везде** (см. ADR-0003):
  `courseState == "ARCHIVED"` — курсы не синхронизируются, их кэш вычищается,
  а API (`_load_assignments`, `/api/courses`, `/api/grades`) исключает их из
  всех ответов на случай устаревших строк в кэше.
- **Кэш зеркалирует API** (`_purge_stale_courses`): после каждого синка из БД
  удаляются все курсы, которых нет в ответе `courses.list` — это покрывает
  ARCHIVED, курсы, из которых студент вышел (unenroll), и удалённые в Google.

## Последствия

- 403-ошибка устранена; синк реальных данных (~700 заданий, 32 активных
  курса) проходит за ~110 с без ошибок.
- Кэшируются только те задания, по которым у пользователя есть сабмишен:
  задания, ни разу не открытые студентом в Classroom, могут не попасть в
  дашборд. Это ограничение самого студенческого API, а не приложения; в UI
  такие задания просто отсутствуют.
- Задания из ARCHIVED-курсов не показываются (решение пользователя) — оценки
  за прошлые семестры на дашборд не попадают.

## Альтернативы

- `courseWork.list` — недоступен студентам (403).
- Батчинг через `BatchHttpRequest` — не поддерживается Classroom (404).
- Отдельный scope `coursework.me.readonly` — не нужен: права уже покрыты
  `student-submissions.me.readonly`; проблема была исключительно в методе.

## Обновление 2026-09-15

Пул на каждый курс и последовательный курсовый цикл заменены стадийной
параллельной синхронизацией с одним общим пулом на весь sync — см.
[ADR-0014](adr-0014-parallel-staged-sync.md). Студенческий маршрут (1) и (2),
таймауты транспорта и thread-local клиенты сохранены без изменений.
