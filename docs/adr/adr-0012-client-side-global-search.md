# ADR-0012: Глобальный поиск выполняется на клиенте (мгновенный дропдаун поверх кэша)

Дата: 2026-09-15
Статус: Accepted

## Контекст

В топбаре была строка поиска с плейсхолдером «Search assignments, subjects,
teachers… (Ctrl+K)», но она была чисто визуальной: `App.tsx` хранил строку и
передавал её в `TopBar`, а фильтрации и навигации не было — ввод ни на что не
влиял.

Бэкенд уже умеет подстрочный поиск — `GET /api/assignments?search=`
(`backend/api.py`) ищет по `title` / `course_name` / `description`. Но это
только задания: без предметов, преподавателей и без ранжирования; фронтенд этот
параметр не использовал.

При этом все данные уже лежат в памяти клиента: `DataContext` при старте грузит
весь список `courses` и `assignments` из локального кэша (ADR-0003, ADR-0004), а
объём — курсы и задания одного студента, то есть сотни записей. Действует
ограничение проекта на минимум зависимостей (ADR-0005).

## Решение

Поиск выполняется **полностью на клиенте**, поверх уже загруженного кэша: ни
новых эндпоинтов, ни запросов к API на каждое нажатие клавиши.

- **Логика** — чистый модуль `frontend/src/lib/search.ts`, функция
  `searchAll(assignments, courses, rawQuery)`:
  - нормализация (нижний регистр, схлопывание пробелов) и токенизация запроса;
    **AND по токенам в любом порядке** — `homework math` и `math homework`
    находят одно и то же;
  - поля и веса: задания — `title` (6), `course_name` (2), `description` (1);
    предметы — `name` (6), `teachers` (2), `section` / `room` /
    `description` (1);
  - скоринг поля: полное совпадение ×3, совпадение с начала слова ×2,
    вхождение в середину ×1; по токенам берётся лучший результат, токены
    суммируются; если хотя бы один токен не найден — сущность отбрасывается;
  - сортировка по убыванию скора, тай-брейк — ближайший дедлайн (задания) или
    алфавит (предметы); лимиты — 8 заданий и 5 предметов.
- **UI** — `TopBar` держит `searchOpen` / `activeIndex` и рендерит
  `SearchResults`: дропдаун под полем с группами «Assignments» / «Subjects»,
  иконками, названием и подзаголовком (предмет + дата для задания,
  преподаватель + кабинет для предмета). Клавиатура: `↑`/`↓` — перемещение по
  результатам, `Enter` — открыть, `Esc` — закрыть, `Ctrl+K` — фокус. Клик по
  фону закрывает дропдаун через `search-backdrop` — тот же приём, что в центре
  уведомлений (ADR-0007).
- **Навигация** — предмет открывает `/subjects/:id`, задание —
  `/subjects/:courseId?assignment=<id>`. `SubjectDetail` читает параметр
  `assignment` и открывает уже существующую модалку `AssignmentModal`; при
  закрытии параметр убирается из URL. Модалка остаётся единственной точкой
  просмотра деталей задания.
- **Локализация** — все строки идут через `t()` с ключами `search.*`
  (`label`, `noResults`, `assignments`, `subjects`) для en/uk/ru (ADR-0011);
  полнота словарей гарантируется `satisfies Record<I18nKey, string>`, то есть
  пропущенный перевод не компилируется.

Решение не противоречит ADR-0004: «производные поля на бэкенде» касается
доменных полей, которые кэшируются и синхронизируются (`is_overdue`,
`priority`), а поиск — это query-time фильтрация представления и к данным в БД
не относится.

## Последствия

- Нулевые сетевые запросы и задержки: результаты пересчитываются на каждое
  нажатие клавиши; поиск работает и при недоступном бэкенде, потому что читает
  кэш из `DataContext`.
- Поиск видит ровно те данные, что уже на экране (включая офлайн-кэш,
  ADR-0003), и не требует отдельной синхронизации поискового индекса.
- Ранжирование изолировано в `lib/search.ts` и не зависит от React — его можно
  покрыть тестами и переиспользовать.
- Появился публичный deep-link `?assignment=<id>`: URL воспроизводит открытую
  карточку (удобно для закладок), но это расширяет контракт `SubjectDetail`.
- Лимиты 8/5 означают, что очень общий запрос показывает не все совпадения —
  сознательный компромисс ради читаемости дропдауна; поднимаются одной
  константой.
- Серверный `GET /api/assignments?search=` остаётся и не удаляется: он не
  используется фронтендом, но полезен для скриптов и отладки. Клиентский поиск
  — надмножество (предметы, учителя, токенизация, ранжирование).

## Альтернативы

- **Использовать существующий `GET /api/assignments?search=`** — отклонено:
  покрывает только задания, без учителей и предметов, без ранжирования, и
  требует round-trip на каждый ввод (или debounce и защиту от гонок ответов).
- **Полнотекстовый поиск на бэкенде (SQLite FTS5)** — отклонено: данные и так в
  памяти клиента, объём личный; FTS добавил бы схему, миграции и endpoint ради
  того, что считается за микросекунды на массиве из сотен записей.
- **Библиотека (Fuse.js / match-sorter)** — отклонено: ADR-0005 (минимум
  зависимостей); нужен только подстрочный поиск с простым скорингом, который
  умещается в один файл без зависимостей.
- **Фильтрация текущей страницы вместо глобального дропдауна** — отклонено:
  плейсхолдер обещает задания, предметы и учителей сразу; страничная фильтрация
  не покрывает кросс-сущностный поиск и переход к найденному.
- **Серверный поиск с debounce и `AbortController`** — отклонено по совокупности
  причин: сложнее, медленнее и требует состояния загрузки при данном объёме
  данных и уже загруженном кэше.
