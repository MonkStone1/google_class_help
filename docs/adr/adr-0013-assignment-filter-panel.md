# ADR-0013: Фильтры заданий — боковая панель, мультивыбор и сохранение между переходами

Дата: 2026-09-15
Статус: Accepted

## Контекст

Вкладка «Задания» (*Assignments*) умела ровно один фильтр — ряд табов над сеткой
карточек, который писал в URL одно значение `?status=todo|overdue|…`. Отфильтровать
задания по предметам было нельзя вообще, совместить два состояния (например,
«к выполнению» **и** «просроченные») — тоже.

Требование: сбоку должна быть кнопка, открывающая панель с фильтром по критериям
«По состоянию» (К выполнению, Просроченные, Выполненные, Оценённые) и «По курсам»
(список всех курсов) с возможностью включить все курсы и выключить все.

Первая итерация (боковая панель + мультивыбор, состояние только в URL) вскрыла
три проблемы: ряд табов дублировал секцию «По состоянию» панели; при переходе на
другую страницу и обратно фильтр терялся, потому что ссылка в сайдбаре ведёт на
`/assignments` без параметров; а асимметрия «пустой выбор = все» для состояний
против «пустой выбор = ничего» для курсов становилась необъяснимой ровно тогда,
когда таб «Все» убирали.

Ограничения проекта: данные целиком лежат в памяти клиента (`DataContext` грузит
весь кэш, ADR-0003/0004), фильтрация — представление, а не домен, поэтому она
остаётся на клиенте (как поиск в ADR-0012); минимум зависимостей и рукописный CSS
на токенах (ADR-0005); весь текст локализуется в en/uk/ru (ADR-0011); настройки
пользователя живут в localStorage (ADR-0006).

## Решение

**Фильтры — только в панели.** Ряд табов над сеткой удалён: два контрола над одним
фасетом расходились бы при мультивыборе (таб подсвечивался только при ровно одном
значении). Вместо них в каждой секции панели есть «Включить все» / «Выключить все»
и счётчик «выбрано/всего», а кнопка «Фильтры» в правом краю строки фильтров
помечается точкой, когда фильтр активен.

**Единая семантика обоих фасетов:** `null` — фасет выключен (подходит всё),
`[]` — не выбрано ничего (не подходит ничего), непустой список — явный allow-list.
Между фасетами — AND, состояния внутри фасета — объединение (OR). Так «Выключить
все» в любой секции означает буквально то, что написано.

**Последний использованный фильтр хранится в настройках** (`gc-settings`, ADR-0006),
новый ключ `assignmentsFilter: { statuses, courses }`. При открытии страницы:

- если в ссылке есть параметры фильтра (`status`/`courses`) — применяется **ссылка**
  (и тут же запоминается, чтобы следующий визит начался с неё);
- если параметров нет — берётся **сохранённый** фильтр.

Любое действие в панели пишет в оба места: в настройки (чтобы фильтр пережил уход
со страницы) и в URL (чтобы ссылка оставалась точной и её можно было сохранить
или переслать). Ссылки остаются точкой входа: `/assignments?status=overdue` из
сайдбара работает как раньше, `?status=all` читается как «без фильтра».

Значения канонизируются: состояния и курсы — в порядке фасета и в порядке курсов
с бэкенда (`ORDER BY name`), поэтому один и тот же набор всегда даёт один и тот же
URL. Неизвестные id курсов отбрасываются. Сохранённый выбор, который **полностью**
устарел (курсы исчезли из кэша или в localStorage мусор), трактуется как «все», а не
как «ничего»: иначе страница выглядела бы сломанной. Намеренно пустой выбор (`[]`)
при этом сохраняется как пустой.

**Код.** Разбор/сериализация, матчинг и применение фильтра вынесены в чистый
модуль `frontend/src/lib/assignmentFilters.ts` (`parseStatusFilter`,
`parseCourseFilter`, `filterAssignments`, `sortAssignments`, `normalize*`,
`sameAssignmentsFilter`) — по образцу `lib/search.ts`, без React. Страница
«Задания» и `SubjectDetail` теперь используют один и тот же матчер состояний и
один сортировщик вместо двух независимых копий. Чтение localStorage проходит
через `normalize*`, чтобы старое или битое содержимое не ломало UI.

Серверная фильтрация не используется: `GET /api/assignments?status=` (и `course_id`)
остаются для скриптов и отладки, панель до них не доходит. Строки — ключи `filter.*`
в en/uk/ru; над сеткой при активном фильтре показывается «Показано X из Y», а если
фильтр отсек всё — пустое состояние с кнопкой сброса.

## Последствия

- Кнопка «назад» больше не отменяет шаги фильтрации: ссылка обновляется через
  `replace`, а состояние живёт в настройках. Фильтр зато переживает и переходы
  между страницами, и перезапуск приложения — это и было требованием.
- Сброс фильтра тоже сохраняется: следующий визит начинается без фильтра.
- Клик по «Задания» в сайдбаре, когда мы **уже** на этой странице, очищает
  параметры ссылки; фильтр при этом остаётся (читается из настроек). В этот момент
  адресная строка фильтр не отражает — единственное расхождение, принято сознательно.
- «Выключить все» в любой секции даёт пустую выдачу. Это честная семантика
  чекбокса; восстановиться помогают счётчик «Показано X из Y», пустое состояние и
  кнопка «Сбросить фильтры».
- Настройки теперь содержат часто меняющиеся данные: каждое действие в панели
  пишет в localStorage. Запись идёт через `sameAssignmentsFilter`, чтобы не
  трогать хранилище, когда значение не изменилось.
- В `AppSettings` появился вложенный объект, который не является «предпочтением»
  в бытовом смысле; при чтении он нормализуется, как `sections` и `notifications`.
- Панель — первый drawer в проекте: классы `.filter-drawer*` рядом с существующими
  оверлеями (`modal-backdrop`, `notif-backdrop`).

## Альтернативы

- **Хранить фильтр только в URL (первая итерация этой же задачи)** — отклонено:
  ссылка в сайдбаре ведёт на `/assignments` без параметров, поэтому фильтр терялся
  при любом переходе; именно это и потребовалось исправить.
- **sessionStorage** — отклонено: ещё один механизм хранения ради того же
  результата, при том что настройки в localStorage уже приняты (ADR-0006) и, в
  отличие от sessionStorage, переживают перезапуск.
- **Фильтр только в настройках, ссылку не трогать** — отклонено: адресная строка
  перестала бы отражать состояние, нельзя было бы перезагрузить страницу или
  поделиться ссылкой с фильтром, а `?status=overdue` из сайдбара перестал бы быть
  точкой входа.
- **Оставить табы состояний как быстрые пресеты** — отклонено по запросу: панель
  и табы управляли бы одним фасетом, и таб подсвечивался бы только при ровно одном
  выбранном состоянии, то есть врал бы при мультивыборе.
- **Асимметрия «пустой выбор состояний = все»** — отклонено: после удаления таба
  «Все» это читается как «0/4 отмечено, но показано всё».
- **Инверсная кодировка «все, кроме…»** — отклонено: экономит длину URL в редком
  случае, зато добавляет второй способ кодирования одного состояния и ветку разбора.
- **Полностью устаревший сохранённый выбор = «ничего»** — отклонено: после
  исчезновения курса из Classroom пользователь получал бы пустую страницу без
  видимой причины.
- **Серверная фильтрация (`/api/assignments?status=&course_id=`)** — отклонено:
  эндпоинт принимает один курс и одно состояние, то есть не выражает мультивыбор
  без новых параметров и цикла запросов; данные и так в памяти клиента.
- **Модалка вместо drawer** — отклонено: панель фильтров не блокирует работу с
  карточками, а модалка `AssignmentModal` уже занята деталями задания.

## Дополнение (2026-09-17): пятое состояние «Без срока сдачи»

В фасет «По состоянию» добавлено пятое значение `no_due` — задания, у которых
срок сдачи не назначен (`due_at is null` на бэкенде). Значение замыкает список
`STATUS_FILTER_KEYS`, поэтому все существующие механизмы (канонизация URL,
сохранение в настройках, «Включить все»/«Выключить все», счётчик) работают без
изменений. Оно добавлено **только** в панель: табы страницы предмета
(`SUBJECT_TABS`) сохраняют прежний набор, чтобы не расширять её UI без
запроса. Матчинг живёт в `matchesStatus` (`!assignment.due_at`), рядом с
остальными состояниями.

Состояния пересекаются: несданное задание без срока подходит и под «К
выполнению», и под «Без срока сдачи», поэтому простое снятие одного чекбокса
просто убирало бы одно из двух совпадений — задание оставалось бы в списке
(сначала замечено при выключении «Без срока сдачи», затем симметрично — при
снятии «Выполненные»/«Оценённые» с оставленным «Без срока сдачи»). В панели
фасет состояний поэтому работает так: `no_due` — **обязательное дополнительное
условие** для заданий без срока (их собственное состояние — «к выполнению»,
«выполнено», «оценено» — тоже должно быть отмечено), а датированные задания
под `no_due` не попадают вовсе. Реализовано в отдельном матчере
`matchesPanelStatuses`, который использует `filterAssignments`; `matchesStatus`
со своей обычной семантикой остаётся для табов страницы предмета. Следствия
приняты сознательно: снятие «К выполнению» прячет и несданные задания без
срока, пока не включён `no_due`; включённый один `no_due` без состояний не
показывает ничего — у заданий без срока не выбрано ни одно состояние.

- **Пятый чекбокс на странице предмета** — отклонено: пользователь просил
  новый пункт только в фильтре «Заданий», а вкладка «Без срока» на странице
  предмета дублировала бы редкий сценарий.
