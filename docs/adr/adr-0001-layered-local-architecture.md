# ADR-0001: Слоистая локальная архитектура без облака

Дата: 2026-09-14
Статус: Accepted

## Контекст

Приложение личное, запускается на одном Windows-ПК и должно работать без
платного хостинга, облачной БД и публичного домена. По промпту требуется
чистое разделение ответственности и запрет «всего в одном файле».

## Решение

Строго слоистая структура, каждый слой знает только о соседнем снизу:

```text
Google Classroom API
        ↓
backend/classroom_api.py   — единственное место с googleapiclient
        ↓
backend/sync.py            — бизнес-логика: синхронизация, derived-поля
        ↓
SQLite (data/classroom.db) — кэш через SQLAlchemy (models.py)
        ↓
FastAPI (api.py, main.py)  — HTTP-граница, Pydantic-схемы
        ↓
React (frontend/)          — только читает кэш через API
```

Всё работает на localhost: FastAPI на 127.0.0.1:8000, Vite dev-сервер на
5173 с прокси `/api`.

## Последствия

- Google-специфика (пагинация, формы дат, названия полей) не протекает
  дальше `classroom_api.py`; заменить источник данных можно, не трогая UI.
- Frontend полностью отвязан от сети: при недоступности Google/UI показывает
  последние кэшированные данные (см. ADR-0003).
- Нет Docker, очередей и фоновых воркеров — для одного пользователя они
  избыточны; синхронизация выполняется в запросе `POST /api/sync` c мьютексом
  от параллельных запусков.

## Альтернативы

- Cloud hosting (Vercel/Supabase) — отклонено: платно и нарушает требование
  локальности.
- Один монолитный `main.py` — отклонено требованием промпта и затрудняет
  тестирование.
