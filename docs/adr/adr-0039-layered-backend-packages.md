# ADR-0039: Слоистые пакеты внутри `backend/` вместо плоских модулей

Дата: 2026-02-10
Статус: Accepted

## Контекст

Плоские импорты, которые ADR-0001 закладывал как «слоистая архитектура», за три
года роста функции превратились в 39 модулей в одной папке. `api.py` вырос до
1692 строк и в одном файле оказались HTTP-хендлеры, SQL-агрегаты, кэш профиля и
сборка Pydantic-моделей; `main.py` — в 517 строк, из которых 310 занимает
`create_app` с четырьмя вложенными middleware-замыканиями.

Ничто этому не мешало: линтер не проверяет размер модуля, тесты не проверяют
направление импортов, CI не запускает типизацию. Один разбитый `sync.py`
(`grading.py` + `sync_store.py` + `sync_service.py` + фасад) показал приём, но
больше не применялся.

Ограничения, которые исключают «просто переложить файлы по папкам»:

* `backend/` добавлен в `sys.path` в восьми местах (тесты, Alembic, четыре
  утилиты в `tools/`);
* desktop-сборка — один exe на Nuitka (ADR-0016), и `path_config.py:48` в
  frozen-режиме считает каталог модуля корнем `dist`, откуда берётся путь к
  встроенному `frontend/dist`;
* тесты патчат приватные символы (`api._cached_profile`,
  `api._profile_cache`, `api.ClassroomClient`, …) — реэкспорт-шимы их не
  спасают, потому что `monkeypatch.setattr(api, "X")` патчит атрибут пакета, а
  не подмодуля;
* OpenAPI-контракт закоммичен и генерирует типы фронтенда: `operationId`
  выводится из имени функции, поэтому переименование хендлера ломает сборку TS.

## Решение

`backend/` остаётся корнем `sys.path`; слоями становятся **пакеты внутри
`backend/`**. Пакет — это просто каталог с `__init__.py`, поэтому плоские
импорты продолжают работать, а `uvicorn main:app`, `Dockerfile CMD`,
`build.bat` и `launcher.py` не требуют изменений.

```text
backend/
├── main.py          # сборка приложения (цель ≤60 строк)
├── edge/            # production edge: lifespan, middleware, origin guard, CSP, SPA
├── core/            # инфраструктура: config, paths, metrics, rate limit, crypto
├── db/              # engine/сессии + models/
├── google/          # единственный контакт с Google API
├── sync/            # store / service / scheduler / worker / background
├── auth/            # identity / ownership / roles / desktop / hosted
├── feedback/        # service / attachments
├── schemas/         # Pydantic-модели ответа
└── api/             # HTTP-слой: routes/ + queries/ + guards + deps
```

`api.py` (1692 строки) разделён на 18 файлов: `api/routes/<ресурс>.py` (тонкие
хендлеры), `api/queries/<ресурс>.py` (чтение кэша, без `fastapi`),
`api/guards.py` (перевод в 404/403), `api/identity.py` (кэш профиля и проекция
`UserOut`/`AuthStatus`), `api/deps.py`, `api/__init__.py` (сборка роутера).

Разрешено единственное направление зависимостей:

```text
core/  ←  db/  ←  google/  ←  sync/  ←  api/routes  ←  main.py
```

`api/queries/**` не импортирует `fastapi`, `api/routes/**` — `google*`,
`sync_store`, `sync_service`. Запрещены `utils.py`, `helpers.py`, `common.py`.

Решение подкреплено двумя механизмами, иначе оно снова размоется:

* `tests/test_api_contract.py` — snapshot путей, методов и `operationId`
  для обоих режимов развёртывания плюс проверка, что каждый хендлер `/api`
  объявлен в `api/routes/`;
* `tests/test_backend_structure.py` (Этап 4) — лимит строк на модуль и
  запрет межслойных импортов.

Отдельно зафиксирован приём, без которого тесты патчат не тот символ:
внутри пакета соседний модуль вызывается **через модуль**
(`from api import identity` → `identity._cached_profile(...)`), а не прямым
`from api.identity import _cached_profile`.

## Последствия

- Добавление фичи перестаёт быть правкой монолита: новый домен — это папка в
  своём слое плюс два роута, а не ещё 300 строк в общий файл.
- `main.py` и каждый домен читаются за один экран; `api/routes/` перечисляет всю
  HTTP-поверхность приложения.
- Проверяемость: `sync_store` (721), `hosted_auth` (666), `config` (548)
  остались нетронутыми в этом же ADR намеренно — их разбиение идёт в Этапе 3
  после того, как слои и проверки уже появятся.
- Плата: тесты, патчащие приватные символы перенесённых модулей, надо править
  (в Этапе 1 — три файла). Это осознанный размен: дешевле, чем ловить
  регрессию в `frontend/openapi.json`.
- `ruff.toml` потребовал только записи новых пакетов в `known-first-party`;
  `pyrightconfig.json`, `pytest.ini` и `.vscode/settings.json` остались валидны
  без изменений, потому что `extraPaths` указывает на каталог, а не на модуль.

## Альтернативы

- **Один пакет `backend/app/{core,api,...}` с импортами вида `from app.core...`** —
  отклонено: ломает frozen Nuitka-сборку (ADR-0016), требует правок в
  `pytest.ini`, `migrations/env.py`, `tools/`, `Dockerfile CMD`, `compose.yml`
  и `build.bat` сразу, а выигрыш даёт тот же — слои уже выражены каталогами.
- **Полное переименование каталогов без пакетов** (`backend/api/routes/...`
  как обычные каталоги) — отклонено: без `__init__.py` не работает включение
  подпакетов, а с ним это и есть пакет.
- **Только разбить `api.py`, не вводя слоёв** — отклонено: `sync_store`,
  `hosted_auth` и `config` остались бы следующими кандидатами на те же 700
  строк, а правила слоёв без проверок в CI размылись бы за один спринт.
- **Рефакторинг с переименованием приватных имён в публичные** — отклонено на
  этом этапе: переименование ломает `monkeypatch`-цели и не даёт выигрыша в
  ясности. Отдельная задача после Этапа 1.
