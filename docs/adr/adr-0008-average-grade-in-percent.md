# ADR-0008: Средний балл считается в процентах

Дата: 2026-09-14
Статус: Accepted

## Контекст

Google Classroom хранит оценки как `assignedGrade` (баллы) и `maxPoints`
задания; максимум у заданий разный (10, 12, 100…). «Среднее по заданиям» в
сырых баллах некорректно: 9/10 и 9/12 — это разные результаты. Промпт требует
не выдумывать оценки там, где данных нет.

## Решение

- Средний балл курса/общий считается как среднее **процентов**
  `points / maxPoints * 100` только по заданиям, у которых есть и балл, и
  максимум (`backend/api.py`, `_course_stats` / `status`).
- Если у задания нет `maxPoints` или оценки — оно в среднее не попадает; при
  полном отсутствии оценок среднее равно `null` и в UI показывается «—».
- Проценты округляются до 2 знаков (курс/общий) и 1 знака (строка оценки).

## Последствия

- Предметы с разными шкалами баллов сравнимы между собой.
- Никаких выдуманных значений: оценка появляется в UI только если Google её
  вернул (`RETURNED` сабмишен с `assignedGrade`). Литеральные оценки
  (A/B/C, зачёт/незачёт) Classroom в поле `assignedGrade` для процентной
  шкалы не отдаёт — такие случаи отображаются как «Ungraded», это ограничение
  API, а не баг приложения.

## Альтернативы

- Взвешенное среднее по дедлайнам/типам работ — отклонено: ни Classroom, ни
  промпт не дают весов, всё взвешивание было бы выдумкой.
- Простое среднее баллов — отклонено: некорректно при разных `maxPoints`.
