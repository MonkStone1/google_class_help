# ADR-0004: Производные поля (статус, приоритет) считаются на бэкенде

Дата: 2026-09-14
Статус: Accepted

## Контекст

Дашборду нужны статусы («overdue», «сдано», «оценено») и приоритет
(HIGH/MEDIUM/LOW), которых нет в Google Classroom API в готовом виде. Промпт
запрещает изменять данные в Google и требует простой автоматической
приоритизации.

## Решение

Приложение полностью read-only по отношению к Google. Производные поля
вычисляются в `backend/api.py` при сборке ответа из кэша:

- `submitted` = `submission.state ∈ {TURNED_IN, RETURNED}`
- `graded` = у сабмишена есть `assigned_points`
- `is_overdue` = дедлайн в прошлом И не сдано
- `priority` = HIGH (overdue или дедлайн сегодня) / MEDIUM (завтра, до 3 дней)
  / LOW (дальше или без дедлайна); расчёт в `sync.compute_priority`

Эти поля существуют только в ответах API и БД-кэше приложения — в Google они
никогда не записываются.

## Последствия

- Единая логика для всех страниц (дашборд, предметы, календарь не расходятся
  в трактовке «overdue»).
- Ночная смена даты пересчитывается на лету — статус не «замораживается» в БД.
- Для сложной будущей приоритизации (веса по баллам и т. п.) точка изменения
  одна — `compute_priority`.

## Альтернативы

- Считать всё на клиенте — отклонено: дублирование логики в каждом компоненте
  и расхождения между страницами.
- Фоновый пересчёт при синхронизации — отклонено: статус устаревает между
  синхронизациями (дедлайн «просрочился», а sync не был).
