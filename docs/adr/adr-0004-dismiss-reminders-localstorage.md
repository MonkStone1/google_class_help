# ADR-0004: Скрытие напоминаний на фронтенде через localStorage

Дата: 2026-09-15
Статус: Accepted

## Контекст

Центр уведомлений (колокольчик в топбаре) показывает напоминания о заданиях
трёх категорий: просрочено / сдать сегодня / сдать завтра
(`buildNotifications` в `frontend/src/components/TopBar.tsx`). Список
пересобирается при каждом рендере из кэша заданий, поэтому любое скрытие
напоминания должно где-то храниться, иначе оно вернётся после перерисовки
или перезагрузки страницы.

Требования: пользователь может убрать одно напоминание (крестик) или все
сразу («Очистить всё»), и скрытые напоминания не появляются снова.

## Решение

- Скрытие хранится в **localStorage**, в существующем ключе настроек
  `gc-settings` (см. `frontend/src/context/SettingsContext.tsx`), как поле
  `dismissedNotifications: string[]` внутри `AppSettings`. Отдельное
  хранилище и серверная часть не используются.
- Ключ скрытия — **`kind:assignmentId`** (например, `overdue:12345`), где
  `kind` — одна из категорий `overdue | today | tomorrow`. Скрытие действует
  только в пределах категории: когда задание переходит в другую категорию
  (например, «сдать завтра» → «сдать сегодня» → «просрочено»), напоминание
  о нём появляется снова — новая категория требует нового внимания.
- Деструктивные действия чисто локальные: крестик скрывает один пункт,
  «Очистить всё» — все видимые; оба записывают ключи через
  `dismissNotification` / `dismissAllNotifications` контекста настроек.
- Кнопка «Сбросить настройки» на странице настроек возвращает
  `DEFAULT_SETTINGS` и, как следствие, очищает список скрытых напоминаний.
- При загрузке массив нормализуется: не-массив и не-строковые элементы
  отбрасываются (защита от повреждённого localStorage).
- Напоминание исчезает само, когда задание сдано (`submitted`) или его
  дедлайн вышел за пределы трёх категорий — скрытие для таких записей
  остаётся «мусором» в localStorage, что для одного пользователя
  незначительно.

## Последствия

- Напоминание, скрытое в одной категории, честно возвращается при смене
  категории — это осознанный выбор в пользу «напоминать о новом статусе».
- Список скрытых растёт монотонно; чистка происходит только через сброс
  настроек. Приемлемо из-за локального, однопользовательского характера
  приложения (в духе ADR-0001).
- История противоречий с сохранёнными данными: до введения
  `kind:assignmentId` ключи были просто id заданий; старые записи после
  обновления не совпадут ни с одним ключом и просто «забудутся» — разовая,
  безвредная потеря скрытий.
- Если в будущем понадобятся напоминания на нескольких устройствах,
  поле придётся перенести в backend (SQLite, ADR-0003) — сейчас это
  избыточно.
