# ADR-0006: Пользовательские настройки хранятся в localStorage

Дата: 2026-09-14
Статус: Accepted

## Контекст

Настройки дашборда (тема light/dark/system, период upcoming 3/7/14 дней,
сортировка по умолчанию, компактные карточки, видимость секций, напоминания,
состояние сворачивания групп на вкладке «Оценки») должны сохраняться между
запусками. Приложение строго локальное.

## Решение

Все предпочтения — в `localStorage` (ключ `gc-settings`), единым JSON-объектом
с дефолтами (`DEFAULT_SETTINGS`) и безопасным мерджем при чтении. Общий шаблон:

- Backend хранит только то, что нужно обоим слоям (данные Classroom, время
  синхронизации, OAuth-токен).
- Frontend хранит чисто UI-предпочтения.

## Последствия

- Настройки работают мгновенно и офлайн; нет лишних эндпоинтов `/api/settings`.
- Настройки привязаны к браузеру-профилю ПК, а не к БД: очистка данных сайта
  сбрасывает их на дефолты. Для одного пользователя на одном ПК это
  несущественно.
- Деструктивные действия (очистка кэша, выход) требуют подтверждения в UI и
  идут через backend; настройки к ним не относятся.

## Альтернативы

- Таблица settings в SQLite + `GET/PUT /api/settings` — отклонено: усложняет
  API ради данных, нужных только одному слою; может быть добавлено позже без
  изменения UI, если настройки должны пережить очистку браузера.
