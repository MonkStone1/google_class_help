# ADR-0007: Центр уведомлений вместо системных нотификаций

Дата: 2026-09-14
Статус: Accepted

## Контекст

Промпт допускает опциональные локальные напоминания; если десктоп-нотификации
сложны для выбранной архитектуры — сначала центр уведомлений внутри приложения.

## Решение

Реализован **центр уведомлений внутри приложения** (звонок в топбаре):
список напоминаний собирается на клиенте из кэша заданий — просроченные, дедлайны
на сегодня, дедлайны на завтра. Каждая категория включается/выключается в
Настройках (`notifications.overdue / dueToday / dueTomorrow`), состояние —
в localStorage (ADR-0006). Пока панель закрыта, на иконке показывается счётчик.

Web Notifications API сознательно не используется.

## Последствия

- Ноль новых разрешений браузера и нулевой риск «тихих» упущенных напоминаний
  из-за закрытого приложения: пользователь видит счётчик при каждом открытии
  дашборда — а дашборд и есть основной сценарий использования.
- Напоминания не приходят, когда приложение закрыто. Это принятый компромисс;
  при желании позже можно добавить `Notification.requestPermission()` поверх
  уже собранного списка `buildNotifications` без изменения структуры данных.

## Альтернативы

- OS-нотификации через отдельный Python-процесс (win10toast и т. п.) —
  отклонено: лишний фоновый процесс и зависимость ради MVP-фичи.
- Email/пуш — отклонено: внешние сервисы запрещены ограничениями проекта.
