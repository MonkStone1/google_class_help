# ADR-0019: OAuth-флоу во владении приложения — свой loopback-callback и единый HTTPS-транспорт

Дата: 2026-09-17
Статус: Accepted
Связанные: [ADR-0002](adr-0002-minimal-oauth-scopes.md), [ADR-0016](adr-0016-production-nuitka-packaging.md), [ADR-0018](adr-0018-single-instance-launcher.md)

## Контекст

Вход в Google выполнялся целиком через `InstalledAppFlow.run_local_server()`
(`backend/auth.py`). Тестер, запускающий exe под Wine на macOS, после согласия
на экране Google получал в дашборде строку `OSError(22, "Invalid argument")` —
и войти не мог.

Что удалось установить по коду и исходникам Wine:

- строка приходит из UI-поля `auth.error`, а туда попадает
  `repr(exc)` из `_run_login_flow` (у sync-ошибок другой формат —
  `OSError: [Errno 22] Invalid argument`), то есть сбой произошёл **внутри
  OAuth-флоу**, а не в синхронизации;
- в Wine `NtStatusToWSAError` возвращает `WSAEINVAL` как fallback для любого
  неотображённого NTSTATUS, а `errno 22` — это `EINVAL`: под Wine такой номер
  означает «непонятный сбой сокетной операции», а не конкретную ошибку;
- внутри `run_local_server` три платформенно-зависимых места:
  `_ExclusiveWSGIServer.server_bind` ставит `SO_EXCLUSIVEADDRUSE` (Wine эту
  опцию мапит в `IOCTL_AFD_WINE_SET_SO_EXCLUSIVEADDRUSE`, но при сбое на
  unix-стороне наружу выходит именно `WSAEINVAL`), ожидание редиректа через
  `wsgiref`/`select`, и обмен кода через `requests`/`urllib3` + OpenSSL;
- у самого `run_local_server` есть известная проблема: он рекламирует
  `localhost`, а биндится только в IPv4 (googleapis/google-cloud-python#18296),
  из-за чего в некоторых окружениях редирект уходит не туда;
- диагностировать это было нечем: в UI уходил только `repr`, трейсбек
  терялся, а сборка релиза идёт без консоли.

## Решение

- **Свой callback-сервер** (`_CallbackServer` на базе `http.server`), привязанный
  к `127.0.0.1` со свободным портом. `redirect_uri` формируется из фактически
  забинденного адреса, поэтому браузер не может отдать код на другой интерфейс;
  `SO_EXCLUSIVEADDRUSE` и wsgiref не используются. Несвязанные запросы
  (favicon, preconnect) не считаются ответом, обрыв соединения браузером не
  прерывает ожидание, тишина ограничена таймаутом.
- **URL согласия публикуется наружу**: пишется в лог и отдаётся в
  `GET /api/auth/status` полем `auth_url`, пока флоу ждёт редирект; в настройках
  дашборда появляется ссылка. Это единственный способ войти, если шелл не может
  открыть браузер (Wine), а консоли в релизной сборке нет.
- **Обмен кода**: сначала штатный `flow.fetch_token` (requests/urllib3), а при
  `OSError` — POST на token endpoint через httplib2, то есть через тот же
  транспорт, которым уже ходят все вызовы Classroom API. Обновление токена
  (`refresh`) устроено зеркально: сначала httplib2, затем requests.
- **`state` проверяется вручную**: обмен «по коду» не проверяет его так, как
  это делает библиотека при передаче полного redirect-URI, поэтому несовпадение
  состояния отклоняет вход.
- **Диагностируемость**: сбои логина и синхронизации пишутся в лог с полным
  трейсбеком (`logger.exception`), в UI остаётся короткая строка.

## Последствия

- Вход больше не зависит от приватного класса `_ExclusiveWSGIServer`, от
  wsgiref и от IPv4/IPv6-несоответствия в redirect-URI; `requests`/`urllib3`
  перестаёт быть обязательным для OAuth и refresh (остаётся первым по очереди).
- `AuthStatus` получил поле `auth_url`; фронтенд показывает ссылку на согласие.
  ADR-0001 не нарушен: слой `auth` остаётся прежним, `api` — тонким.
- Пользователь, у которого браузер не открылся автоматически, всё равно может
  завершить вход (ссылка в настройках и в логе).
- Разбирать платформенные сбои теперь можно по `logs/app.log`: там есть стадия
  (`Google sign-in URL`, `Google sign-in failed`) и полный стек.
- Появился ручной проверочный скрипт `tools/check_oauth_flow.py` (без браузера и
  без реального согласия: одноразовый код подделывается, Google отвечает
  `invalid_grant`), покрывающий callback-сервер, проверку `state` и оба
  транспорта.

## Альтернативы

- Оставить `run_local_server` и попросить у тестера лог — отклонено: трейсбек
  никуда не писался, а сборка без консоли, то есть прислать было бы нечего;
  и тот же дефект повторился бы на следующем Wine-окружении.
- Точечно «починить» `_ExclusiveWSGIServer` monkeypatch'ем — отклонено:
  зависимость от приватного API библиотеки и лечение только одной из трёх
  платформенно-зависимых точек.
- `run_console()` (код вручную через консоль) — отклонено: в релизной сборке
  консоли нет, а UX с копированием кода хуже, чем рабочая ссылка в дашборде.
- Полностью свой TLS/HTTP-стек для token endpoint — отклонено: дублирование
  проверенного кода httplib2/OpenSSL без выгоды.
